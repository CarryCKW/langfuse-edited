### 4. worker/Dockerfile

**文件路径**: `worker/Dockerfile`

**修改内容**: 添加 `sed` 命令处理 Windows 换行符（CRLF）

```dockerfile
# 修改前
COPY --chown=expressjs:expressjs ./worker/entrypoint.sh ./worker/entrypoint.sh
RUN chmod +x ./worker/entrypoint.sh

# 修改后
COPY --chown=expressjs:expressjs ./worker/entrypoint.sh ./worker/entrypoint.sh
RUN sed -i 's/\r$//' ./worker/entrypoint.sh && chmod +x ./worker/entrypoint.sh
```

**原因**: Windows 环境下的 shell 脚本包含 CRLF 换行符，在 Linux 容器中无法正确执行。

## 遇到的问题及解决方案

### 问题 1: LANGFUSE_S3_EVENT_UPLOAD_BUCKET 缺失

**错误信息**:
```
ZodError: [
  {
    "expected": "string",
    "code": "invalid_type",
    "path": ["LANGFUSE_S3_EVENT_UPLOAD_BUCKET"],
    "message": "Langfuse requires a bucket name for S3 Event Uploads."
  }
]
```

**原因**: `env.ts` 中 `LANGFUSE_S3_EVENT_UPLOAD_BUCKET` 是必需字段，即使使用本地存储也需要提供值。

**解决方案**: 在 docker-compose 中添加虚拟值
```yaml
LANGFUSE_S3_EVENT_UPLOAD_BUCKET: langfuse
```

---

### 问题 2: Windows 换行符导致 entrypoint.sh 无法执行

**错误信息**:
```
[dumb-init] ./worker/entrypoint.sh: No such file or directory
```

**原因**: Windows 环境下的 shell 脚本包含 CRLF (`\r\n`) 换行符，Linux 容器无法识别。

**解决方案**: 在 Dockerfile 中添加 sed 命令移除 `\r`
```dockerfile
RUN sed -i 's/\r$//' ./worker/entrypoint.sh && chmod +x ./worker/entrypoint.sh
```

---

### 问题 3: Docker Volume 权限问题

**错误信息**:
```
EACCES: permission denied, mkdir '/app/langfuse-storage/langfuse'
```

**原因**: Docker named volume 默认由 root 拥有，而 Langfuse 容器以非 root 用户 (UID 1001) 运行。

**解决方案**: 添加初始化服务设置开放权限
```yaml
storage-init:
  image: alpine:latest
  restart: "no"
  volumes:
    - langfuse_storage:/app/langfuse-storage
  command: sh -c "mkdir -p /app/langfuse-storage && chmod -R 777 /app/langfuse-storage && echo 'Storage volume initialized'"
```

执行步骤:
```bash
docker compose -f docker-compose-web-custom-v0529-local.yml down
docker compose -f docker-compose-web-custom-v0529-local.yml run --rm storage-init
docker compose -f docker-compose-web-custom-v0529-local.yml up -d
```

---

### 问题 4: 镜像未包含最新代码修改

**错误现象**: 环境变量配置正确，但代码仍然使用 S3 而不是本地存储。

**原因**: 使用的是之前构建的镜像 (`langfuse-web-custom:v0520.2`)，不包含源代码修改。

**解决方案**: 为 web 和 worker 都添加 build 配置，重新构建镜像
```yaml
langfuse-web:
  image: langfuse-web-custom:v0529.1
  build:
    context: .
    dockerfile: web/Dockerfile

langfuse-worker:
  image: langfuse-worker-custom:v0529.1
  build:
    context: .
    dockerfile: worker/Dockerfile
```

## 注意事项

1. **仅限开发环境**: 本地文件存储不适合生产环境，不支持分布式部署
2. **文件持久化**: 使用 Docker volume 确保文件在容器重启后不丢失
3. **预签名 URL**: 通过 API 端点 `/api/public/files` 模拟，需要确保网络可达
4. **批量导出**: 导出的文件将存储在本地，可通过 API 下载
5. **镜像构建**: 修改代码后必须重新构建镜像才能生效
