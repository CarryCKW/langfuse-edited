---
问题分析

根本原因：NEXT_PUBLIC_* 变量在 Docker 构建时未注入

这是问题的核心。NEXT_PUBLIC_* 变量在 Next.js 中是编译时内联的（通过 Webpack DefinePlugin），而不是运行时读取。也就是说：

- 本地开发：NEXT_PUBLIC_* 从 .env 文件运行时读取 → 正常工作
- Docker 生产：NEXT_PUBLIC_* 在 docker build 阶段内联 → 必须在构建时提供

具体问题链

1. Dockerfile 缺少 ARG 声明

查看 web/Dockerfile 的 builder 阶段（第 38-59 行），只声明了 NEXT_PUBLIC_BASE_PATH 等变量的 ARG，但没有声明以下三个变量：

- NEXT_PUBLIC_EXTERNAL_AUTH_ENABLED
- NEXT_PUBLIC_EXTERNAL_AUTH_LOGIN_REDIRECT_URL
- NEXT_PUBLIC_EXTERNAL_AUTH_VALIDATION_MODE

虽然你的 docker-compose 文件中 environment 部分设置了这些变量，但 environment 是运行时环境变量，不是构建时参数。Docker 会静默忽略未在 Dockerfile 中声明的 --build-arg。

2. 构建时变量为 undefined → 客户端行为错误

由于 skipValidation: process.env.DOCKER_BUILD === "1" 在构建时生效（跳过验证），这些未设置的 NEXT_PUBLIC_* 变量会被内联为 undefined。

3. 服务端与客户端状态不一致
┌────────┬───────────────────────────────────┬──────────────────────────┬────────────────────────────┐
│  层级  │               变量                │      Docker 中的值       │            效果            │
├────────┼───────────────────────────────────┼──────────────────────────┼────────────────────────────┤
│ 服务端 │ EXTERNAL_AUTH_ENABLED             │ "true" (运行时 env)      │ 服务端认证逻辑正常工作     │
├────────┼───────────────────────────────────┼──────────────────────────┼────────────────────────────┤
│ 客户端 │ NEXT_PUBLIC_EXTERNAL_AUTH_ENABLED │ undefined (构建时未注入) │ 客户端不知道启用了外部认证 │
└────────┴───────────────────────────────────┴──────────────────────────┴────────────────────────────┘
路由反复跳转的流程

当 access_token 变为不可用时：

1. 用户访问 /langfuse/project/xxx/traces
2. useAuthSession() 被调用
3. isPerRequestExternalAuth() 检查 env.NEXT_PUBLIC_EXTERNAL_AUTH_ENABLED === "true"
→ 返回 false (因为是 undefined)
4. 走到 useNextAuthSessionWithRetry (标准 NextAuth 流程)
5. GET /api/auth/session 被调用
→ 服务端 getServerAuthSession() 检查 isExternalAuthPerRequest() → true
→ 调用 resolveSessionFromExternalAuth() → access_token 无效 → 返回 null
→ session 状态: "unauthenticated"
6. useAuthGuard 判断:
session.status === "unauthenticated" && !isUnauthPath → true
env.NEXT_PUBLIC_EXTERNAL_AUTH_ENABLED === "true" → false (undefined)
→ 走到标准登录重定向: /auth/sign-in?targetPath=...
7. router.replace('/auth/sign-in') → 页面跳转到 /langfuse/auth/sign-in
8. 在登录页:
→ isUnauthPath = true → 不会再触发重定向
→ 但 useNextAuthSessionWithRetry 会重试获取 session (最多2次)
→ 每次重试触发 re-render
→ 如果 session 状态在 "loading" 和 "unauthenticated" 之间切换
→ 可能导致 authGuard 重新计算

但更关键的是，由于客户端不知道外部认证的存在，用户被重定向到 /auth/sign-in 而不是 EXTERNAL_AUTH_LOGIN_REDIRECT_URL。在登录页上，用户无法通过标准方式登录（因为他们使用的是外部认 证），形成了"卡死"或反复跳转的状态。

修复方案

在 web/Dockerfile 的 builder 阶段添加缺失的 ARG 和 ENV 声明：

# 在 builder 阶段（第 59 行之后）添加：
ARG NEXT_PUBLIC_EXTERNAL_AUTH_ENABLED
ENV NEXT_PUBLIC_EXTERNAL_AUTH_ENABLED=$NEXT_PUBLIC_EXTERNAL_AUTH_ENABLED
ARG NEXT_PUBLIC_EXTERNAL_AUTH_LOGIN_REDIRECT_URL
ENV NEXT_PUBLIC_EXTERNAL_AUTH_LOGIN_REDIRECT_URL=$NEXT_PUBLIC_EXTERNAL_AUTH_LOGIN_REDIRECT_URL
ARG NEXT_PUBLIC_EXTERNAL_AUTH_VALIDATION_MODE
ENV NEXT_PUBLIC_EXTERNAL_AUTH_VALIDATION_MODE=$NEXT_PUBLIC_EXTERNAL_AUTH_VALIDATION_MODE

同时，在 docker-compose 的 langfuse-web 服务的 build.args 中也要添加这些参数：

langfuse-web:
build:
args:
NEXT_PUBLIC_BASE_PATH: "/langfuse"
NEXT_PUBLIC_EXTERNAL_AUTH_ENABLED: "true"
NEXT_PUBLIC_EXTERNAL_AUTH_LOGIN_REDIRECT_URL: "https://10.151.18.110:31987/databoard"
NEXT_PUBLIC_EXTERNAL_AUTH_VALIDATION_MODE: "per_request"
