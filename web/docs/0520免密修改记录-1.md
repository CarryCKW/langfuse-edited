## Bug 修复记录

### 问题 1：客户端访问服务端环境变量导致页面空白

**错误信息**：
```
Error: ❌ Attempted to access a server-side environment variable on the client
    at useAuthGuard.useMemo (src/components/layouts/app-layout/hooks/useAuthGuard.ts:76:13)
```

**原因**：`AUTH_DISABLED` 定义在 `server` 部分，是服务端环境变量，不能在客户端组件中直接访问。

**解决方案**：
1. 在 `env.mjs` 的 `client` 部分添加 `NEXT_PUBLIC_AUTH_DISABLED`
2. 在 `runtimeEnv` 部分添加对应映射
3. 前端组件使用 `NEXT_PUBLIC_AUTH_DISABLED` 而非 `AUTH_DISABLED`

**修复内容**：

**文件**: `web/src/env.mjs` - client 部分（第 383-385 行）
```javascript

// <--- mimo modify end --->
```

### 问题 2：创建 Organization 提示无权限

**错误信息**：
```
You do not have permission to create organizations
```

**原因**：Session 中缺少 `canCreateOrganizations` 属性，该属性默认为 `false`。

**解决方案**：在 `trpc.ts` 的默认 session 中添加 `canCreateOrganizations: true`。

---

### 问题 3：创建 Organization 时外键约束失败

**错误信息**：
```
Foreign key constraint violation on the field: `userId`
```

**原因**：默认用户 `auth-disabled-user` 在数据库中不存在，而 `OrganizationMembership` 表的 `userId` 字段有外键约束指向 `User` 表。

**解决方案**：在 `entrypoint.sh` 中添加初始化逻辑，当 `AUTH_DISABLED=true` 时自动创建默认用户。

---

### 问题 4：Docker 部署后仍需要登录

**原因**：`NEXT_PUBLIC_AUTH_DISABLED` 是编译时变量，需要在 `docker build` 时通过 `--build-arg` 传入，而不是运行时。

**解决方案**：在 `Dockerfile` 中添加 `ARG/ENV NEXT_PUBLIC_AUTH_DISABLED`，构建时传入参数。

## 环境变量说明

| 变量名 | 作用域 | 用途 | 设置方式 |
|--------|--------|------|----------|
| `AUTH_DISABLED` | 服务端 | 控制服务端 API 认证 | docker-compose 环境变量 |
| `NEXT_PUBLIC_AUTH_DISABLED` | 编译时 | 控制前端路由守卫和布局组件 | docker build --build-arg |

**注意**：两个变量需要同时设置为 `true` 才能完全禁用认证。
